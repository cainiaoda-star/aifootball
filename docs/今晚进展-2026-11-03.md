## 一、这晚做了什么

### 1. token 自动续期（核心交付）

**问题**：`odds.500.com` 的 `EO-Bot-Captcha-Token` 不是 30 天过期，而是被请求量打掉——实测 20 分钟、约 1,200 次请求就失效。失效后采集静默空转，回补停摆，只能靠人手工跑命令换 token。

**更麻烦的一点**：新开的浏览器会话（Cookie 里没有有效 token）**必定**弹交互式验证，之前那句「真浏览器会自动放行」只在复用旧会话时成立。第一次自动续期尝试就卡在这里（113 秒超时、`脚本未产出新 token`）。

**解法**：用 CDP 模拟点击复选框。

1. `Page.bringToFront` + `Emulation.setFocusEmulationEnabled`（窗口不在前台时鼠标事件可能不被渲染进程接收）
2. 取 `iframe[src*="captcha"]` 的 `getBoundingClientRect()`
3. 在 `(x + 30, y + height/2)` 派发 `mousePressed` / `mouseReleased`
4. 约 3 秒后跳转，token 落种

实测：**全新浏览器配置 → 6 秒内自动通过**，全程无人工。

### 2. 从「手动跑命令」升级为「自愈闭环」

| 组件 | 职责 |
|---|---|
| `TokenHealthService`（新增） | 每 30 秒巡检 `OddsHttp.StatVerify` 增量，≥4 次即触发续期 |
| `TokenRefresher`（新增） | 起 `node harvest.mjs`、回收输出、冷却 8 分钟/每小时 4 次上限、成功即热装载 Cookie |
| `CollectionService`（改） | 回补遇连续 6 次拦截主动中止，不再空转、不把场次误标「无数据」 |
| `/api/token/status`、`/api/token/refresh`（新增） | 状态查询与手动兜底（手动可绕过冷却） |

**为什么按拦截次数而不是定时**：空闲时 token 几小时都不失效，回补时 20 分钟就可能被打掉。定时续期会白开浏览器窗口，按状态触发才刚好。

### 3. 实测结果

**（1）手动触发**

```
POST /api/token/refresh → {"ok":true,"message":"已装载 1 项 Cookie（00:33:03）"}  耗时 9.6s
```

**（2）自愈实战（人为把 token 改成无效值）**

第一版巡检逻辑没通过测试——30 秒窗口内增量永远到不了 4 次，因为每次被拦都会触发全站冷却，
请求速率被压到 1 次/30 秒。改成跨窗口累计后才真正生效：

```
00:38  token 改成 INVALID-TEST-TOKEN
00:39  启动一轮采样
00:40:20  开始续期（触发原因：verify-hits）
00:40:25  已装载 1 项 Cookie
00:43  采样完成：赔率 30 点 / 必发 28 场
```

**从失效到恢复约 2 分钟，全程无人工。** 同时把验证拦截的冷却从 30 秒降到 10 秒，
让「连续 6 次即中止」能在半分钟内触发，而不是占着节流器空等。
