# 半全场大奶改造（2026-11-06）

本文记录「大奶推荐玩法侧重点」从「比分优先」转向「主攻半全场」这一轮改造的完整技术决策、代码改动与待验证点。对应的代码变更集中在 `src/AiFootBall.Sources/MilkPickEngine.cs`，配套改动了模型、仓储、API 与前端。

## 一、为什么改

用户基于三组实盘 / 回测证据，拍板把大奶推荐的玩法优先级从「比分 → 半全场 → 总进球」改成「**半全场 → 总进球 → 比分**」，并放开此前被砍掉的半全场反转档：

1. **必发主胜大热在亚冠 / 欧战是反向信号**（记忆教训 1）：2026-09~11 亚冠 6 场全部押主胜、全部由「必发主胜大热」驱动，命中仅 2/6（33%），远低于整体 54.9%。翻车铁证：大田韩亚 0:0 神户（必发主胜 69.6%）、北京FC 0:1 全北（88.1%）、大阪钢巴 0:1 武里南（79.6%）、鹿岛鹿角 1:3 浦项（96.3%）。
2. **欧罗巴低水热门 = 半全场反转富矿**（记忆教训 1b）：回测 28 场样本，低水热门（主胜 <1.35）反转率 67%，非低水仅 36%。铁证：勒沃库森的平负、桑德兰的负负、伯恩茅斯的胜负、奈梅亨的负胜、水晶宫的负平。
3. **顺风档赔率低还容易翻车**：胜胜/平平/负负起步赔率仅 1.19~3.40（负期望），高赔反转档起步 12.5~16 倍才是大奶。用户明确：「顺风档赔率低，反而大多数还会翻车」。

## 二、半全场 9 组合与档位划分

竞彩半全场 `OptionCode` 形如 `X-Y`：X = 半场结果，Y = 全场结果，编码 3=胜 / 1=平 / 0=负。

| 档位 | 组合 | 半-全场读法 | 起步赔率 | 定位 |
|---|---|---|---|---|
| **高赔反转档**（大奶） | `3-1` 胜平、`0-1` 负平、`0-3` 负胜、`3-0` 胜负 | 半场方向 ≠ 全场方向 | 12.5~16 倍 | 翻盘大奶，最高优先 |
| **零封方向一致档** | `3-3` 胜胜、`0-0` 负负 | 半场即落后、全场零封 | 1.19~3.40 | 零封型剧本 |
| **低赔反转档** | `1-3` 平胜、`1-0` 平负 | 半场平 → 全场分胜负 | 3.1~3.2 | 常见剧本，非大奶 |
| 顺风档 | `1-1` 平平 | 半场平 → 全场平 | 中 | 兜底 |

> 历史注记：2026-11-04 晚曾把半全场改成「只发胜胜/平平/负负」，理由是 453 场全联赛混合样本里逆转档平注回报率仅 0.451。但那没有区分联赛子集——聚焦到「欧战低水热门」后，反转档才是真实价值洼地。本轮据此放开全部 9 个组合。

## 三、四条半全场选注规律（统一决策逻辑）

四条规律在 `MilkPickEngine` 里统一成 `HalfFullTier(MilkPick)` 四层决策（层号越小越优先）：

- **Tier 0 — 高赔反转档**：`HighOddsReverseCombos = {"3-1","0-1","0-3","3-0"}`，翻盘大奶，最高优先。
- **Tier 1 — 零封方向一致档**：某队全场零封对手的模型概率 ≥ `CleanSheetThreshold`（0.15），且方向命中本注 → 优先 `胜胜`（主队零封客队）/ `负负`（客队零封主队）。
- **Tier 2 — 让胜陷阱的胜胜档**：主队让胜（NSPF-3）被买到极端低水（≤ `MinNspfHotOdds`=1.66）且净胜 1 球概率 ≥ `NetOneGoalThreshold`（0.15）→ 主队「只赢球不赢盘」，`胜胜(3-3)` 是正确落点。
- **Tier 3 — 其他**：平平 + 低赔反转档（平胜/平负）。

配套门槛：

- 反转档概率下限单独放宽到 `MinHalfFullReverseProbability = 5%`（顺风档仍 12%），避免一刀切挡掉天然低概率的反转档。
- 强背离撤注（`DivergentDropPct=45%`）对反转档和零封方向一致档**豁免**——它们的价值本质就是「跟市场反着买」，方向相反正是信号本身，不能再被「方向相反 + 市场占比过半」砍掉（此前这个叠加曾导致 2026-11-05 晚 8 场欧罗巴榜上只剩 2 注）。

## 四、零封倾向与让胜陷阱的计算

候选生成时，从 Dixon-Coles 比分网格 `grid`（元素 `(int Home, int Away, double P)`）计算两个信号：

```csharp
// 零封倾向：主/客队全场零封对手的概率
var homeCleanSheet = grid.Where(c => c.Away == 0).Sum(c => c.P) / mass;
var awayCleanSheet = grid.Where(c => c.Home == 0).Sum(c => c.P) / mass;
var cleanDir = homeCleanSheet >= CleanSheetThreshold && homeCleanSheet > awayCleanSheet
    ? '3' : awayCleanSheet >= CleanSheetThreshold && awayCleanSheet > homeCleanSheet ? '0' : (char?)null;

// 让胜陷阱：让胜极端低水 + 净胜1球概率显著
var nspfHome = points.FirstOrDefault(p => p.PlayType == JcPlayTypes.Nspf && p.OptionCode == "3");
var netOneGoal = grid.Where(c => c.Home - c.Away == 1).Sum(c => c.P) / mass;
var hotHomeTrap = nspfHome is not null && nspfHome.Odds <= MinNspfHotOdds && netOneGoal >= NetOneGoalThreshold;
```

这两个信号通过 `MilkPick.CleanSheetDirection`（`char?`）和 `MilkPick.HotHomeTrap`（`bool`）在引擎内部传递，**不落库**（仅引擎内部决策用）。

## 五、玩法名额与排序调整

| 项 | 旧 | 新 |
|---|---|---|
| 玩法顺序 `PlayOrder` | `{BF, BQ, JQ}` | `{BQ, JQ, BF}` |
| 全榜上限 `MaxPicks` | 12（比分5+半全场4+总进球3） | 6（半全场3+总进球2+比分1） |
| 每玩法上限 `MaxPerPlay` | 比分2/半全场2/总进球2 | 半全场3/总进球2/比分1 |
| perMatch 逐场排序 | 按概率降序 | 玩法优先级 → HalfFullTier → 概率 → EV |
