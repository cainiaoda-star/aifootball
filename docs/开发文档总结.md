# AiFootBall 开发文档总结

整理日期：2026-10-31。把 `README.md`、`docs/系统设计说明.md`、`交接文档.md` 和当前代码合成一份。旧文档里已经改掉的说法，集中写在最后一节，以本节和代码为准。

2026-10-31 起，开发可以放在家里的台式机。笔记本这台是已推送的 `main`。家里克隆之后按下面「家里台式机」一节配本机连接串，不要把口令写进文档或提交。

这是一套个人用的足彩 / 数字彩分析系统，跑在本机。足彩侧采集竞彩、北单、胜负彩的受注场次、赔率和必发，按规则给出方向，完场后复盘；数字彩侧在历史开奖之上生成主推 / 备选选号（参考，非必中）。页面顶栏分「体育彩票」和「数字彩」两大类。

| trade.500.com | 竞彩、北单、胜负彩正在卖的场次，以及竞彩固定奖金。竞彩页是 GBK。能不能买按第 5 节：北京时间 9:00 开售、21:58 停售 |

odds.500.com 有 EdgeOne 挑战页。`BotGuard` 从页面正文算出 Cookie，不走浏览器。请求经过全局限速，遇到 429 会放慢。同一时间只应有一个进程在抓这个站，API 调度和命令行不要一起跑赔率。

早期文档里的数量是 2026-10-28 前后的快照：彩票大约 1 万期，足球大约 3900 场，赔率 5 万行以上。之后每天还在加，不要把这些数字当成当前库存。

## 4. 库里跟足彩有关的表

彩票四张表（`LotteryType`、`LotteryDraw`、`LotteryDrawNumber`、`LotteryPrize`）和足球基础表（`FbLeague`、`FbTeam`、`FbMatch`、`FbOdds`）见 `docs/系统设计说明.md`。足彩这条线另外用到：

| 表 | 作用 |
|---|---|
| `FbOddsHistory` | 赔率采样轨迹，不只留初盘和终盘 |
| `FbExchange` / `FbExchangeTrade` | 必发占比 |
| `BettingCard` | 当天受注场次。`Board` 为 `jc` / `bd` / `sfc`，`MatchId` 是 500 的 fid |
| `FbBdHistory` | 北单历史开奖。期号 + 场次号，含让球、平均欧赔、比分和开出 SP |
| `Recommendation` | 落库的推荐。同一 `Board + RecDate + MatchNo` 做 MERGE |
| `LottoRecommendation` | 数字彩选号方案（见 `db/04_lotto_recommendation.sql`）。按 `LotteryCode + TargetIssue + RankNo` 唯一 |
| `Purchase` / `PurchaseLine` | 自己买的票 |
| `UserAccount` | 账号。密码是 PBKDF2-SHA256，10000 次，盐和哈希分开存 |
| `SyncLog` | 每次采集和作业的运行记录 |

约定：

- `RecResult`：`'3'` 主胜，`'1'` 平，`'0'` 客胜。空表示没有方向，胜负彩里当全包。
- 竞彩场次号是「周四001」这种，北单是数字。同一场在不同板块的场次号不同，`MatchId` 才是同一场。
- 亚盘符号：主让为负。
- 复盘和统计按 `MatchId` 去重，同一场跨板块只留最新一条。

## 5. 推荐怎么发

链路：受注场次写入 `BettingCard` → `RecommendationService` 配上公司 0 的欧赔、亚盘升降和必发 → `RecommendationEngine` 给方向和置信度 → `HitProbabilityService` 另写预计命中率 → `RecommendationSelection.ForDisplay` 决定页面和落库留哪些。

方向仍是规则，不是神经网络。信号分（85.7、71.4、61.3 等）是信号分或单日样本，**不是近 60 日命中率**，不能拿来排序，也不能写进说明里冒充长期命中率。近 60 日完场才是依据。

够格进精选（`QualifiesForFeatured`）：按预计命中率排序，不够不凑。门槛停在 **55**，不降到 52。置信度 ≥ 60 只决定复盘是否计入命中率，不是精选门槛。

- 竞彩、胜负彩：信号等级 ≥ 2，且 `HitProbability` ≥ 55。
- 北单只卖让球胜平负。进精选看 `HandicapProbability` ≥ 55，并留下 `RecHandicap`。不让球方向买不到，不能拿它充数。
- 让球绝对值 ≥ 1.5、又没有公司 0 的大小球终盘（`TotalLine` 不大于 0.5）时，不进精选。说明里仍写这条让球，只是不进精选名单。泊松默认总进球 2.6 不是盘口。立博停在 2.5、football-data 的 2.5 也不是主盘。有真实公司 0 盘口的深盘仍按 55% 进。

水位和方向（近 60 日）：

- 不写「低水热门，照发」，也不把置信度抬到 60。≤ 1.50 写明短水命中率高、奖金薄；1.50 到 1.90 写明不是稳胆。
- 小降单独看主、主胜水位 > 1.90，降到等级 1，不进精选（主胜大约四成）。大升单独看客、客胜水位 > 1.90，同样降到等级 1。
- 深盘主让且欧赔主胜 > 1.50，不进精选。≤ 1.50 仍可进。
- 澳超客胜不进精选，也不改成必推主胜。
- 必发 ≥ 75% 的极端大热不追。平局可以标注，不进精选。

够格之后的展示（`RecommendationSelection.ForDisplay`）：

- 竞彩：最多 **8** 场，只发胜平负。不附带比分、让球、进球、半全场。
- 北单：最多 **11** 场，其中预计命中最好的 **8** 场标「强推荐」。也只发胜平负。
- 列表一律按**官方场次号**排：北单 `1→300…`；竞彩 `周一…周日` 再按编号。
- 胜负彩保留全部受注场次。没有方向的场次保留为全包。

销售时间（北京时间，`JcSaleHours`）：每天 **9:00** 开售，**21:58** 停售。21:58 到次日 9:00 之间开赛的场次，过了 21:58 就来不及买，不进推荐，也不进下面的 74 元票。9:00 以后还能买的场保留。

场次：开售时段只留当天那一期，场次号星期等于北京时间今天；9:00 前仍算前一天。周六白天不选「周日xxx」，即使已经能买。21:58 停售到次日 9:00，当天剩下的场次已经买不了，名单同时带上下一期。2026-10-31 22:30 按这条重算，竞彩从 0 场变成 3 场过 55%（周日007 科莫、周日013 拉齐奥、周日017 法兰克福）。北单当时仍是 4 场过 55%。

74 元票和上面 8 场低水胜平负分开（`JcCoverTicket`）：

- 从全部竞彩里另挑 8 场，模型方向的让球水位在 **2.20–4.20**。
- 过关 **6串1+7串1+8串1**。注数 C(8,6)+C(8,7)+C(8,8) = 37，每注 2 元，共 **74 元**，1 倍。
- 错一场还剩不含该场的 7串1 和 6串1。错两场还剩其余 6 场的那注 6串1。
- 让球要打过盘口。澳超客胜不进这张票。
- 页面按钮按让球胜平负填入投注单。票面玩法若是胜平负，保存和结算都不把「让胜」改写成让球，也不套用完场让球盘。

今日推荐走实时 `/api/recommend`。其他日期走已保存的 `/api/recommend/history`。保存任务每天 08:40、11:40、16:40、20:40 落库。北单晚上的场如果那时还没有欧赔或必发，会被门槛挡掉，要等下一次保存或手动保存。

北单历史在 `FbBdHistory`（`db/08_bd_history.sql`），按期号和场次号存让球、平均欧赔、比分和开出选项的 SP。推荐表另有 `Handicap`、`HandicapHit`（`db/07_recommendation_handicap.sql`）。`db/06_recommendation_stale_results.sql` 按完场比分重写被新一期盖住的旧赛果，可以重复跑。`db/oneoff/05_jc_spf_swap.sql` 只纠正 2026-10-31 18:06 之前竞彩 SPF / NSPF 写反的采样，只跑一次，再跑会把新数据换反。

**比分玩法提醒（经验，不是代码规则）：** 比分 SP 返还低，高串抽水叠乘严重；6 场双比分全包 `4+3+2串1` 一类票期望往往很差。实战更宜少场、低串（如 2串1），并以胜平负 / 让球为主仓。

## 6. 预计命中率和复盘命中率

这是两套数，不要混。

- 页面上的「预计命中率」是赛前概率，字段 `HitProbability`（0–100）。
- 复盘上的命中率是已结算场次的 Wilson 区间，带样本量和上下界。
- 胜负彩标题上的「整期连乘」是各场预计概率相乘。比分和半全场仍看官方 SP，不参与这个连乘。

预计概率的做法，按这个顺序：

1. 把胜平负赔率做乘法去水，得到这场的基准概率。
2. 用更早的完场比赛做逻辑回归，特征只有三个：该方向的去水概率、亚盘从初盘到终盘的升降、必发占比。中间一段做保序校准。只有验证集上模型的 Brier 分数明显好于去水时才用模型，否则退回去水。
3. 再用同一方向、同一水位段里已经结算的推荐，向这场的先验收缩。水位段是小于 2、2 到 3、3 到 5、5 及以上。收缩强度 80。6/7 不会被显示成 85.7%。

模型缓存 30 分钟。训练查询失败时，这一段时间退回「去水再收缩」，页面仍有数字。精选同时看信号等级和预计命中率（不低于 55）。置信度 60 只决定复盘是否计入。

### 大奶观察（尾部事件）

与主推（胜平负规则）独立。口径在 `MilkEventTaxonomy`：

| 完场标签 | 含义 |
|---|---|
| `goals7p` | 总进球 ≥7 |
| `hf_win_lose` / `hf_lose_win` | 半全场胜/负、负/胜 |
| `score_other_home` / `score_other_away` | 竞彩标准比分格外的胜其它 / 负其它 |
| `upset_home` / `upset_away` | 主热/客热爆冷（欧赔≤1.50 或必发≥70%，且方向翻车） |

赛前观察标签：`goals7p_watch`、`hf_flip_watch`、`upset_watch`、`score_other_watch`（盘口 / SP / 必发启发式）。

样本 scope：`all`（全库完场）、`card`（竞彩+北单受注∩完场）、`jc`（仅竞彩，可带 SP 中位数）。

接口：`GET /api/milk/stats?scope=&from=&to=`，`GET /api/milk/today`。探针：`_probe/milk_hist.sql`、`_probe/MilkProbe`。页面在「今日推荐」下方精选最多 6 场，**仅观察、不做投注、不生成方案**。

每日复盘把推荐方向和实际半全场的官方赔率标在说明行上。命中和实际赛果用红色，未中用绿色。结算后官方页会把没中的选项收成「--」，库里没有的价格不编。比分赔率只读 `span.sp_value`，避免把比分里的数字当成赔率。

日期用中国时区的本地年月日，不用 `toISOString` 直接当日期。

另有 `wwwroot/summary.html`，是较早的复盘页，主入口是 `index.html`。

## 8. 登录

会话是进程内存里的令牌，大约 24 小时，不是 JWT。重启服务即失效。

注册、登录、当前用户、改密码都在 `/api/auth/` 下。改密码要求当前密码正确，新密码至少 6 位，两次一致，且不能和当前密码相同。改的是当前登录账号。校验用固定时间比较，成功后换新盐。改密码不会刷新上次登录时间。

## 9. 定时任务

标准 5 段 cron，同一天多个时刻的分钟必须相同（11:10 和 16:10 可以，11:10 和 16:30 不行，因为分和时是交叉相乘）。错过的一次，启动后大约 5 秒会补跑。作业串行。

| 作业 | 默认时间 | 作用 |
|---|---|---|
| lotto-daily | 每天 21:45 | 彩票开奖 |
| football-daily | 每天 08:10，回溯 2 天 | 赛程赛果 |
| lotto-recommend | 随调度配置（与开奖衔接） | 生成并保存数字彩选号方案 |
| odds-sample | 每小时第 5 分，向前 **72** 小时；另强制纳入当前在售 `BettingCard` | 欧赔采样（含周末竞彩；避免只采到临近窗口导致精选过少） |
| odds-sample-late | 每 20 分钟 | 临场再采。窗口在代码里是开赛前约 1.5 小时 |
| exchange | 每小时 12、42 分，向前 **72** 小时；单次上限约 350；在售场优先且加密刷新（约 8～12 分钟） | 必发；无盘口的在售场约 45 分钟再探 |
| water-sample | 每分钟，向前 6 小时 | 水位 |
| jc-odds-sample | 每 2 分钟 | 竞彩固定奖金。开售前会报无受注场次 |
| odds-backfill | 每天 03:20，单次最多 1200 场 | 补历史赔率 |
| cards-daily | 每天 **08:30、11:30、16:30、20:30** | 受注场次。开售时间以第 5 节为准，11:30 这一档是刷新，不是开售时刻 |
| save-recommendations | 每天 **08:40、11:40、16:40、20:40** | 紧跟受注场次刷新后落库 |
| settle-hourly | 每小时整点 | 把已完场比分写回复盘 |
| settle-recommendations | 每天 04:00 | 再结算一遍 |

页面上能改的是 cron、是否启用，以及部分作业的提前小时数和重采间隔。`odds-sample-late` 的临场窗口不读页面上的小时数。

## 10. 采集与分析接口

彩票、赛程、赔率覆盖、赔率变化和赛果交叉、单场赔率、作业日志、健康检查，仍是 `README.md` 第五节那些 GET。后来加上的主要是：

- 赔率轨迹、必发、水位、竞彩水位
- 推荐的采集、保存、结算、按日历史、列表
- 每日复盘、复盘查询
- 购买记录、上传、OCR、结算
- 数字彩选号：`/api/lotto/recommend` 等
- 登录、注册、改密码
- `PUT /api/jobs/{name}` 改调度

诊断可以打 `GET /api/health` 和 `GET /api/summary/finished?date=yyyy-MM-dd`。这两个不用登录。临时查库用 `_probe/SqlProbe`，它只打印第一个结果集。

## 11. 票面 OCR（`tools/ocr`）

- 服务：`node ocr-server.js`，监听 `127.0.0.1:5089`。改 `parse-ticket.js` 后需重启 OCR 进程（Node 会缓存 `require`）。
- 上传前必选 kind：`jc-score` / `jc-spf` / `bd-score` / `bd-spf`（及对应 `-app`），避免比分与胜平负串味。
- 北单解析要点：场次号支持 **1～3 位**；解析时保留空格，避免 `吼3`+`4.` 粘成 `34`；过关方式兼容 OCR 把「串」识成「曲 / 康 / 囊」等。
- 拍照：不要用镇纸压住票头（期号 / 流水）和票底（条码 / 二维码），否则识别基本失败。
- 中文队名仍不稳定，数字较稳。录入后优先用场次号回库校对队名。

## 12. 还要注意的限制

- 购买明细和推荐对上，优先 `MatchId`，对不上再用主客队名。队名差一点就匹配失败。
- 胜负彩若数据源没开赔，该场只能全包。
- 同一场推荐历史上有过重复行，查询侧用 `ROW_NUMBER` 留最新一条。
- 推荐方向仍是规则分，不是用大样本重新拟合出来的分类器。预计命中率那一层才会在去水、亚盘和必发上做校准，而且校准失败就退回去水。
- 数字彩选号是频率 / 遗漏等启发式，**不是预测开奖**；页面已标明参考性质。
- 旧文档里的优化项，有一部分已经做了：过程赔率在采样、极端大热不追、长水单信号不进精选、低水不再写「照发」、亚盘冲突降权、命中率改成 Wilson 和收缩、页面可以改调度、可以改自己的密码、赔率/必发窗口扩到 72h 并强制在售场、竞彩最多 8 场、北单最多 11 场（强推荐 8）、官方场次序、数字彩选号。逻辑回归只用于预计概率，没有替换发布用的规则分。没有上神经网络、Elo 或模型堆叠。

## 13. 旧文档里不要再照做的说法
