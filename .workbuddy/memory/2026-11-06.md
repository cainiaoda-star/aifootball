## Ubuntu VPS 部署可行性研究（10:47）
- 用户想买 VPS 把系统部署到 Ubuntu，特别关心定时任务；代码推送的定时任务不在 VPS 上跑。
- 研究结论：**核心可移植**（net8.0 + 内置 Cron 调度器跨平台），但有 5 个必须处理的点：
  1. **数据库 SQL Server 2019+**：VPS 上要跑 SQL Server（mcr.microsoft.com/mssql/server 容器，需 ≥2GB 内存）或连远程 SQL Server。连接串走 `AIFOOTBALL_CONN` 环境变量，已跨平台。
  2. **ListenLocalhost**（Program.cs:14）：服务只监听 127.0.0.1，VPS 外网访问要改成 0.0.0.0 + 反代/防火墙。
  3. **System.Drawing.Common 生成证据 PNG**（RecommendationEvidence.cs）：Linux 需装 libgdiplus + 中文字体（硬编码 "Microsoft YaHei" 需换成 Noto Sans CJK）；仅在 recommend-evidence 定时任务触发，可禁用。
  4. **TokenRefresher 用 where.exe**（Windows 命令）：有 try/catch 兜底返回 "node"，不会崩，但需 VPS 上装 node + Chrome（harvest.mjs 用真实浏览器过验证）；无脚本时自动禁用（可选）。
  5. **OCR 服务**（tools/ocr，Node.js + Tesseract，端口 5089）：跨平台，需装 node + tesseract。
- 定时任务：**完全内置**（NCrontab 3.4.0，JobScheduler.cs），随 API 进程跑，不依赖系统 cron/计划任务。appsettings.json 的 Jobs 段就是完整调度配置，终版 21:50/22:50 也在里面。代码推送不涉及定时任务，天然满足「推送不在 VPS 跑」。
- 部署方式：`dotnet publish` 出 linux-x64 自包含包 → VPS 上 systemd 托管 AiFootBall.Api.dll 即可。deploy-api.ps1 / boot-api.bat 是 Windows 工具，Linux 用 systemd unit 替代。
- 未改代码，只做评估。等用户确认买 VPS 后，再出具体迁移方案 + 补一个 Linux 启动脚本（systemd unit）+ 处理上述 5 点。

## 环境坑：sqlcmd 中文写入的正确路径（本次趟通，00:05）
- 根因：sqlcmd 是中文 Windows 本地化版本（GBK 输出），Git Bash 是 UTF-8 生态，读写都需要转码。
- 读数据（已验证）：`sqlcmd ... -Q "..." | iconv -f GBK -t UTF-8`。
- 写中文（本次趟通）：Write 工具写 UTF-8 SQL 文件 → `base64 -w0` 编码 → PowerShell `[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String(...))` 解码 → SqlConnection 参数化执行。直接 heredoc + `sqlcmd -i` 会静默失败（中文被 GBK 误读破坏 N'...' 字面量，无报错但没插进去）。
- 其他坑：① Git Bash 的 /tmp 映射不到 sqlcmd 可识别路径，SQL 临时文件放工作目录；② PowerShell 双引号里 `$$` 会被展开，sa 口令含 `$$` 必须用单引号字面量；③ FbDailySkill.SkillId 是 IDENTITY 自增列，INSERT 不能显式给值（今晚自增分配了 7）。
- 历史遗留：FbDailySkill SkillId 1~6 的 Title 全是"联赛阶段×卖分"重复（之前落库 Title 传参错误），待用户确认后修正。
