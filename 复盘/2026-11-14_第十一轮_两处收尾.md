## 2. 零计数不能证明是真新队

### 2.1 问题形态（生产实证）

| 竞彩写法 | 库里写法 | 按本名查 | 事件 |
|---|---|---|---|
| 谢周三 | 谢菲尔德星期三 | **0 场** | 74 场（近 18 月，全量 332） |
| 不来梅 | 云达不莱梅 | **0 场** | 58 场（近 18 月） |

两场当时都**静默丢失**（`FbMilkInput` 0 行）：

```
MatchId 1491222  周三005  谢周三 vs 阿克宁顿      2026-11-12 03:00  inputRows=0
MatchId 1428635  周六024  斯图加特 vs 不来梅      2026-11-08 01:30  inputRows=0
```

旧判据下 `games=0` 直接升级为 `new-team` → 核对通过 → 发布，而榜上永远少这两场。
**零计数只说明「用这个名字查不到」，而 `name-unresolved` 的成因本来就是「名字写法不同」**——
同一个零把「新队」与「同一支队换写法」判成同一件事。

### 2.2 改动一：放行前必须有第二条独立事实

`MilkSourceSlate.Verify` 新增 `nameVariants` 参数（`Func<string?, IReadOnlyList<string>?>`），
`name-unresolved`（以及自报的 `new-team`）只有在**两条独立否定都成立**时才升级：

1. 独立库检场次 `< MilkThresholds.MinTeamGames`（第九轮已同源，=3）；
2. 库内**不存在同一身份的相近写法**（`BettingRepository.GetTeamNameVariantsAsync`）。

三种结局都阻断、且互不混淆：

| 情形 | 判定 |
|---|---|
| 场次 ≥ 3 | `队名存疑：库内该队近 18 个月有 N 场…` |
| 场次 0、探查**没做/查不到**（返回 null） | `无法证明是真新队（未做队名变体探查）` |
| 场次 0、探查到相近写法 | `队名存疑：库内存在同一身份的相近写法（谢周三≈谢菲尔德星期三）…` |
| 场次 0、探查为空 | 升级 `new-team`，证据写 `…;dbGames=0;variants=0;min=3` |

「探查没做」与「查到 0 条」是**两件事**：`null` 表示证据不足 → 阻断；空列表才算「查过、确实没有」。

身份闸与解析同一个函数（`TeamNames.SameIdentity`）：`谢周三U21`、`云达不莱梅U19`、`女王公园巡游者U21`
不会被算成「同一支队换了写法」。

**能力边界（明说，不夸大）**：变体探查靠的是名字**包含关系**，能抓前缀/冠名/全称包裹简称
（`云达不莱梅` ⊃ `不来梅`、`大宫松鼠` ⊂ `大宫松鼠RB`）；抓不到**改字**（`不来梅`/`不莱梅`）
与**纯缩写**（`谢周三`/`谢菲尔德星期三`）——这两类只能靠别名表人工登记。
所以它是**必要证据，不是充分证据**；配套动作是 §2.4 的别名，以及「探查缺失一律阻断」。

### 2.3 改动二：`new-team` 不再接受自报

规则表里 `ReasonNewTeam` 原来是 `Accepted = true`：调用方自己写一句 `new-team` 就能绕过两道库检，
与 `engine-skipped` 同一种病（**自报即自证**）。现在 `Accepted = false`，自报的 `new-team`
按 `name-unresolved` **重走同一套判定**；只有核对器自己升级出来的那条才带 `dbGames/variants`。

### 2.4 改动三：补齐两条别名（先核实身份，再入表）

`TeamAliases.Map` 新增：

```csharp
["谢周三"] = "谢菲尔德星期三",
["不来梅"] = "云达不莱梅",
```

入表依据（`FbMatch`，只读）：

| 规范名 | 近 18 月（Status=3） | 同前缀其它写法（**都不许合并**） |
|---|---|---|
| 谢菲尔德星期三 | 74（全量 332） | 谢周三U21 31、谢周三U18 1（梯队） |
| 云达不莱梅 | 58 | 青年队 52、女足 48、U19 34、C队 2、JFV不来梅U19 1、不莱梅港 48（另一家俱乐部） |

生产侧真实链路验证（`team-check`，只读）：

```
不来梅  → 云达不莱梅   本联赛 43 场 / 全库 58 场   认识 是
谢周三  → 谢菲尔德星期三 本联赛  0 场 / 全库 74 场   认识 是
```

- `不来梅`（德甲）现在能被算进来 —— 那次是「认识 → 43 场样本」正常路径，不再走 `name-unresolved`。
- `谢周三`（英锦标赛）解析成功、全库 74 场，但**本联赛 0 场** → 落到 `thin-sample`（规则内、`Accepted`
  的拒绝），而不是「名字缺陷」。这是正确分类：EFL Trophy 没有该队的联赛样本，不该硬出票。
- 计数侧：74 而不是 74+31 —— 梯队**没有**被并进来；`58` 而不是 `58+34+52+48+2` —— U19/青年队/女足/C队没被并进来。

训练集不受影响：`FbMatch` 里没有裸「谢周三」「不来梅」，别名只改变**规范名映射**，
不新增也不合并训练样本。
