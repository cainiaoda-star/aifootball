## 2. 已证实的原因（不是「先归因非确定性」）

### 2.1 程序集属性差异（MetadataReader）

| 包 | `AssemblyInformationalVersionAttribute` |
|---|---|
| `f39db2da` | `1.0.0+`**`91a4547d9a07e9b26746aae2ac74f8a25664fccd`** |
| `afcb40e0` | `1.0.0+`**`9cb7aa76824a34bf9c79083f9dce0ea3a012f6ca`** |

二者均为 **Git 提交完整 SHA**：

| SHA 前缀 | 提交说明 |
|---|---|
| `91a4547` | `docs(复盘): 数字彩正确性收尾材料钉住 12dcb35` |
| `9cb7aa7` | `docs(复盘): 补齐数字彩部署材料（44c17ba基线/指纹/窗口）` |

**时间线**：原包 publish ≈17:05（当时 HEAD=`91a4547`）→ 随后文档提交 `9cb7aa7` → 中止预检 publish ≈17:16（HEAD=`9cb7aa7`）。  
`git diff --quiet 12dcb35 HEAD -- source/` 全程成立 → **业务源码树未变**；变的是 **HEAD 提交被 SDK 写入 InformationalVersion**。

### 2.2 字节差与 MVID

- Core.dll 长度同为 348672。  
- 将两侧 MVID GUID 置零后，剩余差异落在 InformationalVersion 字符串区（及随之变化的元数据校验相关字节），与嵌入的两段 commit SHA 一致。  
- 因此 MVID/`build` 后缀变化是 **InformationalVersion 内容变化的结果**，不是单独的「神秘非确定性」。

### 2.3 SDK / 配置（可证实）

| 项 | 值 |
|---|---|
| SDK | `8.0.427`（Commit `38c6707c62`） |
| Host | `8.0.33` |
| `global.json` | **无** |
| 工程内 `Deterministic` / SourceLink 显式配置 | **无**（csproj 未写） |
| MSBuild `IncludeSourceRevisionInInformationalVersion` | **`true`**（SDK 默认） |
| 默认 `SourceRevisionId` | 来自当前 Git HEAD（未 pin 时） |

**结论**：Git 提交信息**会**参与程序集生成——经 SDK 默认把 `SourceRevisionId` 编进 `AssemblyInformationalVersion`；**仅比对 `source/` 路径不能证明构建输入相同**，因为 HEAD（含仅复盘文档的提交）也是构建输入。
