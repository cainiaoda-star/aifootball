## 4. 停服与正在执行的采样写库（说明，本预检未停服）

### 4.1 代码路径事实

- 调度挂在 `SchedulerHostedService`：宿主 `stoppingToken` 取消时，`JobScheduler.RunAsync` / `RunThroughLaneAsync` 可收到 `OperationCanceledException`（注释写「进程退出，不算失败」）。  
- 采集写库走 `OddsRepository.UpsertAsync` / `ExchangeRepository.UpsertAsync` 等，并把 `CancellationToken` 传入 Dapper；**取消只能阻止尚未发出的命令**，**不能保证**「已进入 SQL Server 的语句/批次」原子回滚——本仓库**没有**对 exchange/water/inplay/jc-odds 的「安全刷盘后退出」协议或事务边界验收。  
- 既有 `deploy-api.ps1` 在停计划任务后对 5088 监听进程使用 **`Stop-Process -Force`**——这是**强杀**，绕过协作式取消；**本次部署不得沿用「直接 -Force」作为默认停服**。

### 4.2 对采样作业正在写入的处理原则

不能只盯出榜作业。下列作业在 `running=true` 时同样在写库（赔率/必发/水位/竞彩采样等）：

`exchange`、`exchange-late`、`water-sample`、`inplay-sample`、`jc-odds-sample`、`odds-sample`、`odds-backfill`、`jc-odds-backfill`，以及出榜/结算/纸面等写路径。

| 情况 | 处置 |
|---|---|
| 任一上述作业（或出榜写作业）`running=true` | **等待**其结束（`GET /api/jobs` 轮询） |
| 等待后窗口不够 / 作业卡死无安全退出依据 | **放弃本窗口**并重新申请 |
| 默认 | **不强杀**（不用 `-Force` 砍进程）；**不自行顺延** |

预检时刻曾见 5 个采样作业 running（含 TIMEOUT/FAILED/STUCK 状态残留）——说明停服窗口必须先清 running，不能假设「只有出榜才写库」。
